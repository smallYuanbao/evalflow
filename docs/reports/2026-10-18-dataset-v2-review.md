## 3. 问题分类

### A. 不可达要点（必须改）

知识库里**一次都没出现**的期望词，机械指标永远不可能命中：

| 题号 | 要点 | 现状 | 证据里的实际说法 |
|---|---|---|---|
| 19 | `飞机抱` | KB 0 篇 | run #21 证据未涉及肠绞痛缓解 |
| 26 | `常见反应` | KB 0 篇 | 证据原文："均属于注射疫苗的**正常反应**" |

`常见反应 → 正常反应` 是明确的改法（KB 13 篇，且当前证据里就有）。
`飞机抱` 需要你决定：换成 KB 里存在的 `排气操`（仅 1 篇），还是删掉这个要点、只保留 `哭闹`。

### B. 同义词 / 改写（建议改）

语义对、字面不对。这类问题会让机械指标系统性偏低：

| 题号 | 期望词 | 证据里的实际用词 | 建议改为 | KB 支持 |
|---|---|---|---|---|
| 15 | 补水 | 补液 | `补液` | 13 篇 |
| 17 | 揉腹 | 按摩肚子、顺时针按摩 | `按摩` | 48 篇 |
| 18 | 拍嗝 / 竖抱 | 轻轻拍宝宝的后背、打出奶嗝 / 将宝宝坚起来 | `奶嗝` / `竖起来` | 3 / 8 篇 |
| 22 | 勤换尿布 | 尿不湿、纸尿裤换新 | `勤换` 或 `尿不湿` | 11 / 17 篇 |
| 20 | 满6个月 | 6个月左右 | `6个月` | 175 篇 |
| 25 | 就医 | 及时带他去儿科或皮肤科看一下 | `皮肤科` 或保留 | 3 篇 |

> 18 题的证据里还有一个 KB 错别字：「将宝宝**坚**起来」。建议顺手修知识库（坚→竖），否则用哪个词都别扭。

### C. 真实检索失败（保留，不改数据）

这 3 条题的要点在知识库中**可达**，但 run #21 没召回相关内容：

- **24 夜里闹腾**：证据是肠绞痛/缺钙/断夜奶，没有出牙、睡眠倒退、环境因素。
- **28 半夜哭醒**：证据是缺钙/微量元素/受惊吓，没有肠绞痛、出牙、就医。
- **16 咳嗽有痰**：`就医`、`化痰` 可达，但证据只有拍痰、喝水等护理建议。

保留它们——这是被测系统的真实短板，也是评测集的价值所在。

### D. 库外题拒答判定

run #21 的 `rejection = 0.25`，但实际情况是：

| 题号 | baby-ai 的回答 | 机械判定 | 实际情况 |
|---|---|---|---|
| 30 换轮胎 | "这个问题可不归我管啦～我是小熊育儿助手…" | 0（漏判） | **拒答了**，但词表没有"不归我管" |
| 31 北京景点 | "这是 B 类问题哈～推荐几个北京经典景点…" | 0 | 确实没拒答 |
| 32 Python 爬虫 | "抱歉，我只能回答育儿相关问题哦～" | 1 | 正确 |
| 33 股票开户 | "这个问题和育儿无关，我简单说两句…" | 0 | 确实没拒答 |

真实拒答率是 **2/4**，机械指标报的是 1/4。建议补充拒答词表（如"不归我管""不展开说"），这是指标问题，不是数据问题。

### E. `gold_scores` 的来源与可用性

- 16 条库内题有 gold，4 条库外题没有。
- 没有任何一条的 5 个指标能同时与某次 run 完全吻合，所以**不是整批从某次 run 抄的**。
- 但 **item 27** 的 gold（`faithfulness=0, answer_relevance=0, answer_correctness=0, context_recall=0.65, context_precision=0.2`）与 run 12–18 的打分高度吻合，而这几轮里 item 27 的输出是：
  - run 12/13/14：**空字符串**
  - run 16/17：**"抱歉，当前服务繁忙，请稍后再试～"**
  - run 18：**"参考资…"**（截断）
  
  也就是说，这条 gold 很可能是在**被测系统故障样本**上标的。
- run #21 的校准结果（MAE 0.09–0.24、corr 0.06–0.61）也说明当前 gold 不足以证明 judge 可信。

**建议**：修订 v3 后，gold 重新标注；记录标注人、日期、依据。标注前先确认样本是正常回答。

### 知识缺口 run #23

### 注意事项

1. **rejection 从 0.25 升到 0.75 不代表被测系统变好了**：本次回答措辞恰好命中了
   拒答词；其中 Python 那题是「口头说超出范围、实际仍作答」的假阳性。
   拒答指标仍是启发式，单次 run 数值不能当稳定结论。
2. **v3 的分桶均值不可与 v2 直接比**：`皮肤-开放` 拆出了 1 条，
   `dataset_hash` 变化会被平台标记为不可比。
3. **gold 仍未重标**：校准结论继续不可用，下一步应在 run #22 的干净 trace 上
   重新人工打分。
4. **运行环境**：宿主机休眠后 celery worker 会静默失去 broker 连接，
   任务留在 redis 队列但无人消费（run 停在 `progress=0`）；重启 worker 即可恢复。

### 已知问题（未修）

- API `--reload` 触发 `_recover_stale_runs()`，会把 worker 仍在执行的 run 临时标成
  failed（run 结束又被 `_mark("done")` 覆盖）。评测期间避免编辑文件，或把
  `--reload-dir` 限制到 `backend/`。
