# EvalFlow Ch28 设计:裁判 A/B —— 评测方法本身也要被验证

## 定位

不是新功能。是**验证评测方法**的一次实验,由「面试官视角自审」引出:
EvalFlow 生成和裁判用同一个模型(评自己的 toy pipeline 时),有 self-preference 风险。

**结论不是「证明了偏袒」,而是更硬的一条:裁判模型本身就是个变量,且它的方差大到能淹没门禁。**

## 实验设计

**配对比较**,不是重跑评测:

| | 基线 | 实验 |
|---|---|---|
| 输入(问题/回答/证据) | 取自 Run 10 已存的 trace | **完全相同** |
| 裁判 | `deepseek-chat` | `qwen3.8-max-0902`(通义,跨模型族) |
| 生成 | deepseek-v4-flash(baby-ai) | 不重跑 |

**为什么这样设计**:
- 输入完全一致 → 分数差异**只能**来自裁判,不被生成随机性污染;
- 不重跑被测系统 → 省时省钱;
- **不动生产代码**:脚本用 `llm.chat_json = ...` 替换底层客户端,prompt 模板/温度/解析逻辑全部原样。

**两个必须对齐的细节**(否则对比不公平):
1. **JSON mode**:原 `chat_json` 带 `response_format={"type":"json_object"}`,替换时也必须带——
   否则混进了「有没有强制 JSON」这个变量。
2. **解析失败返回 None**,与原实现一致。

## 结果(Run 10,3 条库内样本)

| 指标 | deepseek-chat | qwen3.8-max | Δ | n |
|---|---|---|---|---|
| faithfulness | 0.1000 | 0.2333 | +0.13 | 3 |
| context_precision | 0.4250 | 0.5000 | +0.08 | 2 |
| **context_recall** | **0.5000** | **0.8900** | **+0.39** | 3 |
| answer_relevance | 0.6000 | 0.4500 | **−0.15** | 3 |
| answer_correctness | 0.4000 | 0.3667 | −0.03 | 3 |

**逐条看,单样本波动更大**:「宝宝咳嗽有痰怎么办」的 `answer_relevance` 从 0.9 → 0.45(Δ −0.45),
`context_recall` 从 0.5 → 1.0(Δ +0.5)。**同一份回答、同一份证据,换个裁判差半档。**

## 这个数字意味着什么

**门禁的 `max_regression` 容忍度是 0.05,而换裁判让 `context_recall` 动了 0.39 —— 7.8 倍。**

也就是说:**如果两次 run 之间换了裁判,门禁会报出一个巨大的「回归」或「改进」,而它跟质量毫无关系。**

> 这条比「DeepSeek 可能偏袒自己」严重得多:门禁是 EvalFlow 用来**做发布决定**的东西,
> 而它的输入(指标)本身有 0.39 量级的裁判方差,却被当成 0.05 量级的可信信号。

## 一个反向的好消息

**`faithfulness` 低这个结论是稳的**:两个裁判都判它很低(0.10 / 0.23)。
所以 Ch26 那个发现(「baby-ai 检索到证据却不用」)在换裁判后依然成立——**它是真的**。

**能扛住换裁判的结论,才是可信的结论。**

## 诚实的边界

- **n = 3**(库内样本只有 3 条),只够演示现象,不够下精确结论。有一条 `context_precision` 调用失败(n=2),已如实列出。
- **不能归因成「偏袒」**:通义的判断能力和 DeepSeek 不同,Δ 里既有「偏好差异」也有「能力差异」。
  能站住的说法是:**裁判选择是个未受控的变量**。

## 由此得出的改进方向(本章不做,留作后续)

1. **把裁判模型写进 run 快照**:和知识库/prompt 版本一样,它是可复现性的一部分。
   换裁判 = 换了一个测量仪器,必须记下来。
2. **门禁容忍度要跟裁判方差对齐**:0.05 的容忍度配 0.39 的裁判方差,等于没有容忍度。
   合理做法是先测出裁判的方差(重复打分同一批样本),再定容忍度。
3. **裁判可配置**:`JUDGE_BASE_URL/KEY/MODEL` 独立于 `CHAT_*`,这样才能做 A/B 和交叉验证。

| | 旧(拍脑袋 0.7 / 0.05) | 新(校准) |

## 补充:n=16 的复测 + 与「重跑噪声」合并

初步结论只有 3 条样本。扩到 20 条评测集后,对 Run 12 的 **16 条库内样本**重做换裁判对比:

| 指标 | deepseek-chat | qwen3.8-max | Δ | n |
|---|---|---|---|---|
| faithfulness | 0.1700 | 0.2233 | +0.05 | 15 |
| context_precision | 0.3862 | 0.6106 | **+0.22** | 16 |
| **context_recall** | 0.4794 | 0.7923 | **+0.31** | 16 |
| answer_relevance | 0.7031 | 0.6813 | −0.02 | 16 |
| answer_correctness | 0.6562 | 0.6156 | −0.04 | 16 |

n=3 时的结论(0.39)在 n=16 下复现(0.31)——**不是小样本假象**。

极端个案:「九个多月还不会爬正常吗」的 `faithfulness` **0.0 → 1.0**。一个裁判说「完全不忠实」,
另一个说「完美忠实」。同一份回答、同一份证据。

### 两类噪声,影响不同的指标

| 指标 | 同配置重跑极差 | 跨裁判 Δ | 裁判固定的容忍 | 裁判可变的容忍 |
|---|---|---|---|---|
| faithfulness | 0.072 | 0.053 | **0.09** | 0.09 |
| context_precision | 0.024 | **0.224** | **0.03** | **0.29** |
| context_recall | 0.000 | **0.313** | **0.02** | **0.41** |
| answer_relevance | 0.134 | 0.022 | **0.17** | 0.17 |
| answer_correctness | 0.181 | 0.041 | **0.24** | 0.24 |
| （当前 GATE_RULES) | | | 0.05 ❌ | 0.05 ❌ |

**分界很清晰**:
- **重跑噪声**落在**生成侧**(回答每次重新生成 → faithfulness / answer_relevance / answer_correctness 会动);
- **跨裁判噪声**落在**上下文侧**(`context_recall` / `context_precision` —— 裁判对「证据覆盖了多少」的尺度差异极大)。

**两类噪声影响的是不同的指标** —— 所以不能只测一种就下结论。

### 由此得出的关键工程结论

> **把裁判模型固定下来(写进 run 快照、不随意更换),能把容忍度收紧 20 倍。**
>
> `context_recall` 的容忍度:裁判固定时 **0.02**,裁判可变时 **0.41**。

这不是「加个配置」,而是「**明确一个测量约定**:同一组对比必须在同一个仪器下做」。
和「天平称东西前先归零」是一回事。

**顺带**:当前 `max_regression = 0.05` 对**两种情形都太低** —— 裁判固定时它高于噪声尚可接受,
裁判可变时它比噪声低一个数量级,门禁会持续误报。

## 噪声图完整版:三个来源,两种药方

补测第三个来源——**同一裁判重复打同一批 trace K=3 次**:

| 指标 | 同分率 | 最大抖动 | 平均抖动 |
|---|---|---|---|
| faithfulness | **100%** | 0.000 | 0.000 |
| context_recall | **100%** | 0.000 | 0.000 |
| context_precision | 88% | **0.350** | 0.028 |
| answer_relevance | 94% | 0.100 | 0.006 |
| answer_correctness | 94% | 0.050 | 0.003 |

**裁判基本上是「确定的仪器」**(`temperature=0` 起作用了),但不是完全确定。

⚠ **要分清层级**:`context_precision` 单条抖 0.35,但**聚合层**(16 条平均)只抖 0.028/√16 ≈ 0.007。
看聚合指标时它可忽略;下钻看**单条 trace** 时要留意。

### 三个来源合并

| 指标 | 生成随机 | 跨裁判 | 自复现(聚合) | **合计·裁判固定** | **合计·裁判可变** | 收紧倍数 |
|---|---|---|---|---|---|---|
| faithfulness | 0.072 | 0.053 | 0.000 | **0.09** | 0.09 | 1.0× |
| context_precision | 0.024 | **0.224** | 0.007 | **0.03** | **0.29** | **9.3×** |
| context_recall | 0.000 | **0.313** | 0.000 | **≈0**(保守取 0.02) | **0.41** | **∞** |
| answer_relevance | 0.134 | 0.022 | 0.002 | **0.17** | 0.17 | 1.0× |
| answer_correctness | 0.181 | 0.041 | 0.001 | **0.24** | 0.24 | 1.0× |

### 两种噪声,两种药方(这是本章最有用的结论)

| 噪声来源 | 影响 | 药方 | 成本 |
|---|---|---|---|
| **跨裁判** | **上下文侧**(context_precision / context_recall) | **固定裁判模型**(写进快照) | **免费** |
| **生成随机** | **生成侧**(faithfulness / answer_relevance / answer_correctness) | **多跑几次取均值** | 要钱 |

**这两个药方互不替代**:
- 固定裁判,生成侧指标的容忍度**一点都收不紧**(1.0×)——因为它抖在别处;
- 多跑取均值,上下文侧也没必要——因为那里本来是确定的。

**所以「把容忍度全面收紧到 0.05」在生成侧是做不到的**,除非把跑的轮数加上去
(生成噪声 σ≈0.13~0.18,要压到 0.05 需要多轮平均)。

**加上第三个来源后的完整结论**:
> 裁判是**确定的仪器**(自复现性可忽略),所以噪声主要来自**「选哪个模型」和「每次重新生成」**。
> 前者**免费可锁**(固定裁判),后者**只能靠多跑**。而现在的 `max_regression = 0.05`
> 两者都没覆盖到。
