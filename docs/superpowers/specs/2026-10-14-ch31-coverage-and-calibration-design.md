# EvalFlow Ch31 设计:指标覆盖率 + 第一次真正的人工校准

## 定位

收「可信」这条线的最后两块:

1. **指标覆盖率** —— 分数不说「基于几条样本算出来的」。
2. **人工校准实操** —— Ch18 建了校准机制却**从没被真正使用过**;这次真跑一次。

顺带:为准备校准而读数据时,**在 baby-ai 里挖出一条四层因果链的 bug**(单独提交在 baby-ai 仓库)。

---

## 一、指标覆盖率

### 问题

`aggregate_run` 只返回各指标的**均值**,不返回「基于几条算的」。

```
scores: {'faithfulness': 0.1594, ...}   # 20 条里评上了几条?
```

现在库里的 NULL 分数是 0%,所以还没出事。但**一旦 judge 开始失败**(限流/超时/模型抖动):

> 20 条里挂了 17 条 → 均值只由剩下 3 条算出 → 界面显示「忠实度 0.9」,看起来很健康

而**挂掉的往往是最难/最长的样本** → 剩下的是简单样本 → **均值系统性偏高**。这比「没有分数」更容易误导。

### 决策

`Score` 在 judge 失败时**仍写一条 value=NULL 的行**(不是不写),所以两个数都算得出来:

```python
"score_coverage": {
    "faithfulness": {"scored": 16, "attempted": 16},   # 应该评几条 / 真的评上几条
    ...
}
```

- `attempted` 由「有该指标行的 trace 数」得出 —— **自动适配分桶**(库内指标 16、rejection 4),不需要额外逻辑。
- 前端指标卡旁显示「采样 16/16」,低于 80% 标黄并提示。
- **门禁**接入:`MIN_COVERAGE = 0.8`,低于它就**不给判定**,note 写明「样本不足(x/y 评上,均值不可信)」。

**理由**:和 Ch26/Ch29 同一个模式 —— **结论的前提不成立时,系统必须说出来**。
「均值基于几条」正是这个结论的前提之一。

**不通过的原因因此分成四类**,不再混为一谈:
`未评` / `样本不足` / `低于阈值` / `较基线下降`。

## 二、第一次真正的人工校准

### 为什么

Ch18 建了 `gold_scores` + bias/MAE/Pearson 的机制,**但从没被真正使用过**——
「建了但没用过」本身就是个短板,而且它无法回答最根本的问题:

> **尺子稳不稳**(Ch28 量了) ≠ **尺子准不准**(没人验过)。

### 做法

1. 重跑一次评测**(先修掉 baby-ai 的三个 bug,见下)**,拿到干净数据;
2. 逐条读「问题 + 检索证据 + 回答」,**人工给 5 个指标打 0~1 分**,共 16 条;
3. 走 `PUT /datasets/3/items/{id}/gold` 写入;
4. 取 `GET /runs/18/calibration` 的报告。

### 结果

| 指标 | bias | MAE | Pearson | n |
|---|---|---|---|---|
| **faithfulness** | **−0.138** | 0.237 | 0.549 | 16 |
| context_precision | −0.067 | 0.173 | 0.750 | 16 |
| context_recall | −0.033 | 0.172 | 0.758 | 16 |
| **answer_relevance** | +0.016 | **0.041** | **0.978** | 16 |
| answer_correctness | **+0.106** | 0.106 | **0.929** | 16 |

### 三条结论

**① `faithfulness` 裁判系统性偏严 −0.138**(n=8 时 −0.131,**两次一致**)

这**解释了它为什么一直只有 0.17 的低分** —— 不全是 baby-ai 差,有一份是**裁判的尺度**。

**② 偏差按指标分方向,不统一**

faithfulness 偏严、answer_correctness 偏松。**所以「加一个统一修正量」是错的。**

**③ 偏差在「比较」中抵消,在「绝对值」中不抵消**

- 门禁的**绝对阈值**(`min`)在 judge 尺度上 —— Ch28 校准的那批值要按 bias 打折;
- 门禁的**回归判定**(比两次 run)用同一个裁判 → **bias 自动抵消**。

> **「回归门禁」比「绝对阈值门禁」更可信。** 这是本章最实用的一条。

### 一个戏剧性的小样本对照

`answer_relevance` 的相关系数:**n=8 时 0.315 → n=16 时 0.978**。

n=8 时它看起来「排序能力很差」,其实是**最准的指标**。**纯属小样本假象**——
而这正是 Ch28 已经写下过的警告(「n=3 的极差有 ~50% 相对误差」),现在拿到实证了。

## 三、附:为准备校准而在 baby-ai 挖出的 bug

读数据时发现 **16 条里 3 条回答是空的**,而且该会话后续请求全 500。挖下去是一条四层链:

| 层 | 缺陷 |
|---|---|
| 1 | `call_deepseek` 返回 `content` 时不检查是否为空(SDK 类型是 `str \| None`) |
| 2 | 空答案被写进**答案缓存** → 之后所有相同提问都命中空答案,不自愈 |
| 3 | 空答案被写进**会话历史** → `ChatHistoryEntry(content='')` 校验失败 → 500 |
| 4 | `get_history` 读时不设防 → 老数据里的空行让会话**永久** 500 |

**真正的根因还要再上一层**:模型换成了 `deepseek-v4-flash`(**推理模型**),
但 `max_tokens` 还是 1000(给非推理模型定的)。推理模型先输出 `reasoning_content` 再输出 `content`,
两者共用预算 —— 真实 RAG prompt 下思维链本身就超 1000,`content` 因此为空。

实测:
```
max_tokens=2048 → content=0 字符,   reasoning=3316 字符
max_tokens=4096 → content=395 字符, reasoning=2946 字符
```

**四层里少查任何一层,都只会看到表象**(缓存命中 / 服务不稳定 / 偶然空回复)。

三个 commit 都在 baby-ai 的 `feat/eval-meta-endpoint` 分支。

## 本章不做

- **用 bias 反推修正后的阈值**:需要更多金标准样本才稳,且要让「judge 尺度」与「人的尺度」的换算关系有依据。
- **第三种失败模式(回答被截断成 3 字符)的检测**:它不是「没评上」——裁判给了准确的 0 分。
  属于被测系统的输出质量问题,不是评测平台的判定问题。**评测把问题暴露出来就够了。**
