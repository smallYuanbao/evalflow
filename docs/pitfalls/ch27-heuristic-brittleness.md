# Ch27 踩坑:机械启发式对「措辞」极脆(且失效是静默的)

> 这一章修的是**评测平台自己**的缺陷。它由 Ch26 接真实系统暴露——评自己的数据时永远遇不到。

## 坑:关键词表在自己数据上完美,换个系统就整体失效

**现象**:Ch26 评 baby-ai 时,两条库外题的 `rejection` 都判 **0.0**(=没拒答)。人工看 trace,
baby-ai **明明拒答了**:

> 「抱歉，我只能回答育儿相关问题哦～ 换汽车轮胎属于汽车维修领域，不在我的专业范围内」

**根因**:`rejected()` 是关键词表匹配:

```python
REJECT_MARKERS = ["不清楚", "不知道", "无法回答", "无法提供", "没有相关", "没有证据", "无法给出"]
```

baby-ai 说的是「**我只能回答**…」「**不在我的专业范围内**」——**一个词都匹配不上**。

**为什么以前没暴露**:EvalFlow 之前评的是自己的 toy pipeline,那些回答是**我们自己写的**,
措辞天然贴着词表。**用自己的数据测自己的词表,等于自己批改自己的卷子。**

**修法**:扩词表,按「意图」分组(不知道/没有证据 + 超出范围/只答某类)。

**修完还没完——词表第一版写太死了**。第一版加的是「**我**只能回答」,结果下一个 run 里
baby-ai 说成「**只能回答**育儿相关问题」(少了个「我」),照样漏:

| 库外题 | 这次的措辞 | 判定 |
|---|---|---|
| 汽车换轮胎 | 「**我只能回答**育儿相关问题」 | ✅ |
| 北京旅游 | 「**只能回答**育儿相关问题」← 没有「我」 | ❌ |

> 同一个模型、同一个问题,**换个 run 措辞就会漂**。词表不能贴着某一次的输出写——
> 要用**最宽的公共子串**(「只能回答」),不是抄原句。

改宽之后:6 条库外 trace 全部 1.0,库内题不受影响。

**原理**:**关键词匹配是「用有限的说法去覆盖无限的说法」**,必然漏。它在封闭数据上看起来完美,
只是因为那些数据是照着它写的。一旦被测对象换成「别人写的回答」,覆盖度立刻现原形。

**更危险的是失效方式**:它**不报错**——分数照常算出来,只是算错了。没有异常、没有日志,
只有人工读 trace 才能发现。所以这类问题**必须靠「换个系统试试」或「人工抽查」来暴露**,
靠跑测试是发现不了的(测试用的还是自己写的句子)。

## 附带两条

**一、词表要「宽」不要「抄原句」**:抄原句会带上某一次输出的偶然成分(比如多一个「我」),
下次措辞一漂就漏。取的是**语义上的公共子串**。

**二、测试用例不要用「理想化的句子」

第一版可能想写 `assert rejected("我不清楚，无法回答") == 1.0` —— 这是**贴着词表编的句子**,
测了等于没测。**直接用真实回答原文**(含 emoji、markdown、口语化表达)才防得住回归。

而且要把**不同 run 的不同措辞**都收进用例——上面那条「少了个我」的漏判,
正是靠对比两次 run 的原文才发现的。

## 小结

两句:**「用自己的数据测自己的规则」是自欺——规则和数据同源,永远测不出覆盖不足**;
**启发式的失效往往静默,所以要么人工抽查,要么换数据源验证**。
接新被测系统时,第一件事是**人工读几条它实际的输出**,而不是直接信分数。
